# ポジションサイジング / 建玉管理ツール

日本株デイトレード（フェニックス戦略・A型戦略）向けのポジションサイジング計算機と、建玉（保有ポジション）管理を1枚の `index.html` にまとめたツールです。

GitHub Pages: https://lapislapinbleu.github.io/trading-tools/

ビルド不要・単一HTMLファイル完結（React 18 UMD + Tailwind CDN、外部依存はCDN読み込みのみ）。スマートフォン（iPhone片手操作）を想定したモバイル縦画面ファーストのUIです。

## できること

- **サイジング計算機**
  - フェニックス（監視27銘柄・一覧UI）: タブ表示時に同一オリジンの `daily_prep.json` を自動fetchし、優先順位（緑→黄→前場売買代金順）で27行を並べて自動入力。通常は1行サマリ（優先順位・銘柄名・区分バッジ・GC状態・株数・リスク額）、タップで展開すると前引け値・前場安値・前場高値・ATR・SL・TP・トレール発動・momentum_hintに加えてエントリー株数・ref_price・約定値を編集できる
  - フェニックス各行のSLはATR対応: daily_prep.jsonの実測ATR14を自動入力（上書き可）。手入力があれば最優先、無入力なら「前場高値」から自動推定、いずれも無ければ従来通り0.3%下限のみ（詳細は下記「SL計算式とATR入力」）
  - **エントリー株数は編集可能**（デフォルト=自動計算値。約定後にSL距離が広がった場合など、手で減らせる）。株数変更時はリスク額・建玉代金を即時再計算し、リスクが上限7.7万円を超えると赤警告（約定値入力があれば(約定値−SL)×株数、無ければ(前引け値−SL)×株数で判定）
  - 各行に任意入力で「発注直前の現在値（ref_price）」「約定値」を記録可能（サイジング計算には使わない。両方入力時はスリッページを参考表示）
  - A型（発注可能3銘柄: ルネサス・フジクラ・村田製作所）: 2本目始値・高値からショート想定の推奨株数を算出
  - 監視リスト27銘柄（緑20・黄7）との照合、重複・セクター上限・金融クラスタ上限・指値限定の自動チェック
  - 各行の「この内容で建玉登録」はワンタップで直接建玉登録（建値=約定値優先・無ければ前引け値、株数=編集後の値、TP=建値×1.06で再計算）。**保有5件に達している場合、または既に保有中の銘柄は登録不可**（保有中の行は登録ボタンの代わりに「既に保有中の建玉です」と表示）。登録後は建玉管理タブへ自動切替、上部に一時通知バナーを表示
  - 登録前の制約警告（建玉代金上限・リスク上限・5件超・日次上限・重複・セクター・金融・黄区分・指値限定）を各行にリアルタイム表示（警告のみで登録はブロックしない項目と、ハード制限で登録自体をブロックする項目＝5件超・重複がある）
- **建玉管理**
  - 建玉の登録・編集・トレール発動トグル・決済
  - 前引け値／前場安値／エントリー値／約定値／備考（メモ）を建玉に記録可能（手動登録フォーム・編集フォームどちらも任意入力。備考は建玉カードに表示され、決済履歴にも引き継がれる）
  - 保有中建玉を含めたサマリー（保有銘柄数・建玉代金合計・想定最大損失合計・当日確定損益・日次損失上限警告）
  - 決済履歴（直近20件表示。バックアップは全件対象）
  - サイジング側の違反チェックに保有中建玉を合算（重複・セクター上限・金融クラスタ上限）
  - CSVエクスポート／インポートによるバックアップ（建玉・決済履歴のみ。サイジング入力は対象外）。コピペ用のテキストエリア方式に加えて、CSVファイルのダウンロード／ファイル選択インポートにも対応

## 昼の準備シート（同一オリジン配信・rulebook v1.9対応・27銘柄一覧UI）

12:35の即時エントリーとサイジング正確性を両立するため、前場終了後に監視27銘柄の発注準備値を自動計算する仕組みです。仕様は `jq/fullmarket/specs/daily_prep_sheet_spec.md` および `jq/fullmarket/specs/trading_tools_list_ui_spec.md`、生成側はこのリポジトリの `daily_prep.py` + `.github/workflows/daily_prep.yml`（平日11:35/11:50/12:05 JST〈昼休み〉・15:35/15:50 JST〈大引け後〉の計5回に自動生成・commit・push）を参照してください。

- フェニックスタブを表示すると、同一オリジンの `daily_prep.json`（GitHub Pagesの同じホストに生成される。URLは相対パス `daily_prep.json`）を自動fetchします。「再読込」ボタンで手動再取得も可能
- 取得すると27行の一覧に前引け値・前場安値・前場高値・実測ATR14が自動入力され、優先順位（`優先順位`フィールド＝緑→黄→前場売買代金順）でソートされます。株数編集・ref_price・約定値は再読込しても保持されます
- 表示内容: 取得時刻・データ日付・complete状態（前場データが全銘柄揃っているかの警告）
  - データ日付が本日と異なる場合は赤警告（古いデータの可能性）。当日データだが `complete:false`（11:30バーが未完備の銘柄がある）場合はamber警告
  - GC状態が負（前場GCがまだ成立していない）銘柄はグレーアウトし「新規GC待ち」と表示
  - 成行不可銘柄には「成行不可」バッジ（対象はdaily_prep.json側の `no_market_order` フラグに準拠）
- `daily_prep.json` が未取得・取得失敗の日は、各行を展開して前引け値・前場安値・前場高値・ATRを手入力すれば通常どおりSL/TP/株数が計算されます（GC状態・momentum_hint等の参考表示欄は未取得時は「―」表示のまま。手入力対象外）

## 保有期限・寄成返済の運用（rulebook v1.9）

フェニックスの保有期限はエントリー日を1日目として5営業日目（＝エントリー+4営業日）です。この期限日までにTP／SL／トレールで決着しなければ、**期限日の大引け後（夜間）にIFD-OCO注文を取消し、翌営業日（＝エントリー+5営業日、期限日の翌営業日）の寄成（寄付成行）で返済**します。建玉管理タブの各建玉カードには「期限日（5営業日目）」と「寄成返済日」を土日・祝日・年末年始等の東証休場日をスキップした営業日ベースで自動計算して表示し、当日が期限日ならアンバー系バッジで「今夜OCO取消→明日寄成で返済」、当日が寄成返済日以降なら赤系バッジで「本日寄成で返済」を強調表示します。サマリーパネルにも該当件数バッジが出ます。祝日データは2027年末まで収録済みで、それ以降は `index.html` 内の `JP_HOLIDAYS_2026_2027` 配列の更新が必要です。

## トレール引上げ判定UI（rulebook v1.9 §2.3・trail_check_ui_spec.md）

含み益+1.5%（建値×1.015＝トレール発動ライン）に到達した建玉は、次の変更機会（昼休み・大引け後、ほか9:00-9:30/12:30-13:00の場中窓）にSLを建値へ引上げます（**現在値が建値未満でも実施**）。この判定を見落とさないよう、建玉管理タブの各建玉カード（`trailArmed=false` のもののみ）にトレール判定行を表示します。

- **判定材料**: `daily_prep.json` の各銘柄に配信される `day_high`（当日ザラ場全体の高値）・`pm_high`（12:35以降のバーの高値。エントリー当日はこちらのみを使用し、エントリー前の前場高値を混入させない）
  - 昼休み実行（11:35/11:50/12:05）時点では `day_high` は前場高値と同値・`pm_high` は `null`
  - 大引け後実行（15:35/15:50）で当日の全データが揃う
- **観測最高値の累積**（`max_high_seen`）: JSONを読み込むたびに、建玉ごとに観測した高値の最大値を localStorage（`trail_max_high_v1`。建玉idキー）へ累積更新します。更新規則: JSONの `date` > 建玉の `entryDate` なら `day_high`、`date` == `entryDate` なら `pm_high` を候補値とし、既存値より大きい場合のみ更新（下がることはない）。候補値が `null` の回はスキップ
- **表示**:
  - 到達（観測最高値 ≥ 建値×1.015）: アンバー強調「トレール引上げを実施: SL→建値◯◯円に変更（現在値が建値未満でも実施）」＋「引上げ済みにする」ボタン（既存のトレール発動トグルを起動）
  - 未到達: 「未到達: 観測最高値◯◯円 / 発動ライン◯◯円（あと+◯.◯%）」
  - 観測データなし（JSON未取得、または当該銘柄のデータが無い）: 「判定データなし（手動確認）」
  - 判定行付近に、使用した `daily_prep.json` の `generated_at`（例: `判定データ更新: 8/3 15:35`）を小さく表示。15:30チェック時に古い11:35版しか無い場合に気づけるようにするためのものです
- サマリーパネルに「トレール引上げが必要な建玉: N件」バッジ（アンバー、0件時は非表示）
- 判定は5分足高値ベースの参考値です。境界付近はチャートで確認してください（カード内に同旨の注記あり）

## SL計算式とATR入力（rulebook v1.9・SL式のATR項）

rulebookのSL式は次の通りです。

```
SL = 前場安値 − max(0.3%×前引け値, ATR)
```

以前の計算機はATR項が欠落しており（`SL = 前場安値×(1−0.3%)` 相当）、実弾のOCO設定が恒常的にタイト側（浅すぎるSL）へ乖離していました。現在はATR項を実装し、フェニックス各行の展開表示に「バッファ◯◯円 = ◯◯」という形で、SLがどの根拠（ATR入力値／推定ATR／0.3%下限）で決まったかを明示します。

### ATR_used の優先順位

`ATR_used = 手入力値 > 自動推定値 > 0`（＝未入力かつ推定不能なら従来通り0.3%のみが下限として採用されます）

1. **手入力（最優先）**: 各行の「ATR（円・実測値／JSON自動入力・上書き可）」欄に、TradingViewの5分足ATR(14)・SMA・**12:30足時点**の値を入力すればそれが最優先で使われます
2. **自動推定（手入力が無い場合のみ）**: 「前場高値」を入力すると、以下の式で自動推定します

   ```
   ATR推定 = max(p_code × 前引け値, c_global × (前場高値 − 前場安値))
   ```

   - `p_code`: 銘柄別定数（過去実績のatr_confirm/前引け値の中央値）。`index.html` 内 `ATR_PCODE` にハードコード
   - `c_global`: 前場レンジ比例の全銘柄共通定数。`index.html` 内 `ATR_C_GLOBAL`（現在値 0.109023）
   - 監視リスト外銘柄で `p_code` が無い場合や「前場高値」未入力の場合は、算出できる方の項だけを使います
3. **どちらも無い場合**: 0.3%下限のみ（ATR項=0として従来通り動作）

この推定式・定数は `jq/fullmarket/audit_atr_approximation.py` による検証（監視27銘柄・直近12ヶ月の全営業日、真値=エンジンのatr_confirmとの比較）で、候補式のうち「SL価格のズレが株価の0.2%を超える日の割合」が最小だったハイブリッド式を採用したものです。詳細は `jq/fullmarket/results/atr_approximation_study.md` を参照してください。四半期の監視銘柄再選抜時は、このスクリプトを再実行して `ATR_PCODE` / `ATR_C_GLOBAL` を更新してください。

### SBIアプリでの数値の読み方（リアルタイム運用）

実運用ではSBI証券スマホアプリのチャートでリアルタイム判断を行うため、ATR指標は表示できません。アプリの通常のチャート・気配画面で読める次の3つの数字だけで入力できます。

- **前引け値**: 前場の最終値（11:30の終値）
- **前場安値**: 前場（9:00〜11:30）の安値
- **前場高値**: 前場（9:00〜11:30）の高値（ATR自動推定を使う場合のみ必要。手入力ATRを使うなら空欄でも可）

### TradingViewでATRを確認する場合（過去データ確認時のみ）

TradingViewは前日までの過去データ確認にのみ使用し、以下の設定でATR(14)を表示してください。

- 足種: **5分足**
- 平滑化: **SMA**（Wilderではない）
- 参照する値: **12:30の確定足**時点のATR(14)の値

この値を各行の「ATR」欄にそのまま入力すれば、自動推定より優先して使われます。

## データはすべて端末内・localStorage保存

サーバーへの送信は一切行いません。すべてのデータはブラウザの localStorage にのみ保存されます。

### `sizing27_v1`（フェニックス27行一覧の入力永続化。日付付き・バックアップ対象外）

```json
{
  "date": "2026-08-03",
  "edits": {
    "5803": { "entry": "4199", "morningLow": "4130", "morningHigh": "4339", "atrManual": "32.86", "qty": "", "refPrice": "", "fillPrice": "" },
    "8306": { "...": "27銘柄コード分" }
  }
}
```

`edits` は銘柄コード（4桁）をキーとした辞書で、行ごとの `entry`（前引け値）・`morningLow`（前場安値）・`morningHigh`（前場高値）・`atrManual`（ATR・円）・`qty`（エントリー株数・空文字なら自動計算値を使用）・`refPrice`（発注直前の現在値）・`fillPrice`（約定値）を保持します。`date` が本日と異なる場合は起動時に `edits` を空にリセットします（日付が変わったら自動クリア）。`daily_prep.json` の自動fetch成功時は `entry`／`morningLow`／`morningHigh`／`atrManual` のみ上書きされ、`qty`／`refPrice`／`fillPrice` は保持されます。

サイジングタブ「入力をクリア」ボタンは `sizing27_v1` の `edits` のみを空にします（A型タブの入力には影響しません）。

### `atype_v1`（A型入力の永続化。バックアップ対象外）

```json
{ "c2open": "1500", "c2high": "1545" }
```

旧バージョンで使われていた `sizing_v1`（フェニックス5枠＋A型入力の共有キー）は現在使用していません。既存の `sizing_v1` データが端末に残っていても読み込みエラーにはならず、単に無視されます（移行処理は行いません）。

### `positions_v1`（保有中の建玉、配列）

```json
{
  "id": "一意なID",
  "code": "銘柄コード（4桁）",
  "name": "銘柄名（監視リスト外は code と同一）",
  "sector": "セクター名（監視リスト外は null）",
  "entryDate": "YYYY-MM-DD",
  "qty": 100,
  "entryPrice": 4800,
  "slPrice": 4636.05,
  "tpPrice": 5040,
  "trailArmed": false,
  "refPrice": 4805,
  "fillPrice": 4810,
  "morningClose": 4800,
  "morningLow": 4650,
  "note": "任意メモ"
}
```

`refPrice`（エントリー値）・`fillPrice`（約定値）・`morningClose`（前引け値）・`morningLow`（前場安値）はいずれも任意・null許容です。フェニックス一覧の「この内容で建玉登録」でのワンタップ登録時に自動格納されるほか、建玉管理タブの手動登録・編集フォームからも入力できます。旧バージョンで保存された建玉（これらのフィールドが無い）もそのまま表示・編集できます。

### `trail_max_high_v1`（建玉ごとの観測最高値。トレール引上げ判定UI用）

```json
{ "建玉のid": 4820.5 }
```

建玉id（`positions_v1` の `id`）をキーとした辞書で、`daily_prep.json` の `day_high`／`pm_high` から累積更新した観測最高値を保持します。値が未設定の建玉は「判定データなし（手動確認）」表示になります。決済・削除された建玉のキーは次回のJSON読込時に自動的に取り除かれます。バックアップ（CSV）対象外です。

### `closed_v1`（決済履歴、配列）

```json
{
  "id": "一意なID",
  "code": "銘柄コード",
  "name": "銘柄名",
  "sector": "セクター名またはnull",
  "entryDate": "YYYY-MM-DD",
  "closeDate": "YYYY-MM-DD",
  "qty": 100,
  "entryPrice": 4800,
  "closePrice": 4900,
  "pnl": 10000,
  "refPrice": 4805,
  "fillPrice": 4810,
  "morningClose": 4800,

```

決済時、建玉が保持していた `refPrice`／`fillPrice`／`morningClose`／`morningLow` はそのまま決済履歴に引き継がれます。

## バックアップ（CSV形式）

建玉管理タブ最下部「バックアップ」パネルから、建玉（`positions_v1`）・決済履歴（`closed_v1`）を1本のCSVとしてエクスポート／インポートできます。**サイジング入力（`sizing_v1`）はバックアップ対象外**です。

エクスポート／インポートはそれぞれ2通りの方法があります。

- **テキストエリア方式（コピペ）**: 「エクスポート」ボタンでテキストエリアに出力→コピー。「インポート」欄にCSVを貼り付けて「インポート」ボタン
- **ファイル方式**: 「CSVファイルをダウンロード」ボタンで `kentama_backup_YYYY-MM-DD.csv`（当日の日付）としてファイル保存。「CSVファイルを選択してインポート」ボタンでファイル選択ダイアログを開き、CSVファイルを選ぶと自動で読み込まれます

ダウンロードするCSVファイルには先頭にUTF-8 BOMを付与しています。Excelでそのままダブルクリックで開いても日本語（銘柄名・メモ等）が文字化けしません（テキストエリアへのコピペ出力はBOMなしのままです）。インポート側はテキストエリア・ファイルどちらの方式でも、先頭にBOMが付いていても自動的に除去してから読み込みます。

### CSVスキーマ（1行目ヘッダ固定・全19列）

```
type,id,code,name,sector,entryDate,qty,entryPrice,slPrice,tpPrice,trailArmed,refPrice,fillPrice,morningClose,morningLow,closeDate,closePrice,pnl,note
```

| 列 | 内容 |
|---|---|
| `type` | `position`（保有中の建玉）または `closed`（決済済み） |
| `id` / `code` / `name` / `sector` / `entryDate` / `qty` / `entryPrice` / `note` | 共通項目 |
| `slPrice` / `tpPrice` / `trailArmed` | `position` 行のみ使用（`closed` 行は空欄） |
| `refPrice` / `fillPrice` / `morningClose` / `morningLow` | 両方の行種別で使用（未入力なら空欄） |
| `closeDate` / `closePrice` / `pnl` | `closed` 行のみ使用（`position` 行は空欄） |

- エクスポートは建玉→決済履歴の順に**全件**出力します（決済履歴の画面表示は直近20件のみですが、CSVには制限がありません）
- 値に `,`（カンマ）・`"`（ダブルクォート）・改行を含む場合は `"..."` で囲み、内部の `"` は `""` にエスケープします（最小限のRFC4180準拠）。銘柄名やメモにカンマ・改行を含めても壊れません
- 数値はカンマ区切りなしの素の数字、未入力の値は空文字です
- インポート時はヘッダ形式（1行目が `type` から始まる19列）と各行の型（`qty`・`entryPrice` が数値であること等）を検証し、不正な場合は貼り付け内容を一切変更せず赤字でエラー表示します。検証を通れば `confirm` ダイアログの確認後、現在の建玉・決済履歴を丸ごと置き換えます
- **旧バージョン（JSON形式）のバックアップはインポートできません**（後方互換なし）。JSON形式のテキストを貼り付けるとヘッダ検証エラーになります
- Excel・Googleスプレッドシートに貼り付けてそのまま集計できる形式です。**決済履歴CSVはrulebook §0のスリッページ月次集計（ref_price=エントリー値 vs 約定値）にそのまま使えます**

## iOS Safari のデータ消失に関する注意（重要）

iOS Safari には ITP（Intelligent Tracking Prevention）という仕組みがあり、**サイトを7日間開かないと localStorage が自動的に削除されます**。ホーム画面のショートカットではなく、通常のSafariタブ・ブックマークからの利用のみだと、この7日ルールの対象になります。

### 対策

1. **少なくとも週1回はこのページを開く**（ITPのカウントがリセットされます）
2. **「ホーム画面に追加」を強く推奨**: Safariの共有メニューから「ホーム画面に追加」を行うと、ホーム画面から起動するWebアプリは独立したストレージコンテナとして扱われ、ITPの7日削除の対象になりにくくなります
3. **バックアップ機能で定期的にCSVをエクスポートしておく**（建玉管理タブ最下部「バックアップ」パネル）。万一データが消えてもインポートで復元できます。特に長期保有中の建玉がある場合は登録・変更のたびにエクスポートしておくことを推奨します

### iPhone（Safari）でのCSVファイル入出力について

- **ダウンロード**: 「CSVファイルをダウンロード」をタップすると、Safariの標準的なダウンロード動作（共有シート経由、または自動的に「ファイル」App内のダウンロードフォルダへ保存）になります。保存先は端末の設定に依存します
- **アップロード**: 「CSVファイルを選択してインポート」をタップするとファイル選択画面が開き、「ファイル」App・iCloud Drive・On My iPhoneなど、端末内やクラウド上に保存したCSVファイルを選んで読み込めます
